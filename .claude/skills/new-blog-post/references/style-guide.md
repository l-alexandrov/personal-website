# Writing style guide

This guide is drawn from the existing site copy (`sections/intro.mdx`, `sections/about.mdx`). It's a starting point; refine it as posts are written.

## Voice
- First person, conversational and direct. ("Hey there! I'm a problem-solver at heart…")
- Confident but not salesy. Focus on solving real problems for people and businesses.
- Practical back-end perspective: Laravel, PHP, CI/CD, WebSockets, project management, B2B software.
- Personal interests (travel, politics) can show up as colour, but they aren't the focus.

## Structure
- Open with the problem or a concrete situation, not with a definition.
- Keep paragraphs short (2–4 sentences). Use subheadings every few paragraphs.
- Prefer concrete examples and real code over abstract advice.
- End with a takeaway or next step, not a generic "thanks for reading".

## Mechanics
- English: American spelling, sentence-case headings.
- Bulgarian: standard literary Bulgarian. Keep established English tech terms (Laravel, queue, deploy) where a Bulgarian developer would, and avoid forced calques.
- Use the en dash (–) for ranges and avoid em-dash chains.
- Keep code identifiers, CLI commands and product names untranslated.
